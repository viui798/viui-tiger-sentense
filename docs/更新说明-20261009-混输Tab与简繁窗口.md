# 更新说明：英文段 Tab 选重 + 简繁向前看窗口（v0.2.6）

日期：2026-10-09

本版两处改动，都只影响对应功能，不涉及方案定义与用户数据。

## 一、中英混输：英文段里 Tab 选重后可以接着打字

### 之前的问题

在英文段（`[` … `]`）里输入英文时会出现多个词典联想候选，Tab **能移动高亮**，但接着打字不会用上选中的候选——输入串还是原来的字母。

### 现在的行为

当处于英文段、且刚才按过 Tab 时，按字母或空格会**先把组合串里正在输入的那个英文词替换成高亮候选里的英文词**，再接上本次按键。

| 操作 | 结果 |
|---|---|
| `[hell` → Tab 选中 `hello` → 按 `w` | `[hellow`（补全后接着打字） |
| `[hell` → Tab 选中 `hello` → 按空格 | `[hello `（补全 + 空格，可接着打下一个词） |
| `[hell` → Tab 两次选中 `hells` → 按 `w` | `[hellsw` |
| `[hell` → 不按 Tab 直接按 `w` | `[hellw`（原行为不变） |
| `[hell` → Tab 后 Shift+Tab 退回「原样输入」→ 按 `w` | `[hellw`（不替换） |

### 实现与限制

- 新增 `correction.accept_inline_tab_selection(env, state, context, typed)`，在英文段的字母分支与空格分支里先尝试它。
- 通过 `context:get_selected_candidate()` 取高亮候选，再从候选文本末尾取出英文词（因此中文前缀不会干扰）。
- **前端需要提供 `context:get_selected_candidate()`**：代码里做了类型判断，缺失时会静默回退到旧行为（Tab 仍能移动高亮，只是接着打字不替换）。桌面端（鼠须管/小狼毫）都有，手机端建议实测。
- 实现细节：`lua/tiger_sentence.lua` 的局部变量已达 Lua 的 **200 上限**，所以辅助函数挂在 `correction` 表上而不是新建 `local`。

## 二、简繁转换：整句转换的向前看窗口 6 → 16

### 之前的问题

`super_replacer.segment_convert` 里写死 `MAX_LOOKAHEAD = 6`，而 `STPhrases.txt` 里有 **883 条长度超过 6 字**的条目（最长 16 字，多为俗语与长句）。这些条目是专门用来消歧的，窗口太小就**永远匹配不到**，只能逐字转换，于是出现：

| 输入 | 改前（窗口 6） | 改后（窗口 16） |
|---|---|---|
| 不干不淨吃了没病 | 不**幹**不淨 ❌ | 不**乾**不淨 ✅ |
| 人如风后入江云 | 人如風**后**入江雲 ❌ | 人如風**後**入江雲 ✅ |
| 先天下之忧而忧后天下之乐而乐 | …而憂**後**天下之樂 ❌ | …而憂**后**天下之樂 ✅ |
| 全彩干式印表机 | 全**綵**乾式印表機 ❌ | 全**彩**乾式印表機 ✅ |
| 于斯納爾斯貝里 | **於**斯納爾斯貝**裏** ❌ | **于**斯納爾斯貝**里** ✅ |

### 效果与代价

- 883 条长词条中 **46 条结果修正**。
- **无回归**：日常常用词 top 5000 与诗词语料 3000 条，在 6 字与 16 字窗口下结果**完全一致**。
- 代价：每个位置最多多试 10 次查表（有 `fmm_cache` 缓存），而且**只在繁体档位**才会运行这个滤镜，简体档位不受影响。

## 五、升级方式

覆盖两个 Lua 文件即可，然后重新部署并完全退出重启前端：

```
lua/tiger_sentence.lua
lua/wanxiang/super_replacer.lua
```

简繁的 LevelDB 缓存（`lua/replacer.userdb`）**不需要重建**——本次改的是算法窗口，不是转换表。

## 六、回滚

`git revert` 对应提交，或 `git checkout v0.2.5 -- lua/tiger_sentence.lua lua/wanxiang/super_replacer.lua`，然后重新部署。
