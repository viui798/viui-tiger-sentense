# 性能优化：合并辅助翻译器 + 历史捕获节流

日期：2026-11-03。目标：在保留全部功能的前提下，减少 librime-lua 每次翻译创建的
`LuaTranslation` 数量（鼠须管插件在每个对象析构时执行全量 Lua GC），并减少每键临时表分配。

## 改动

1. **辅助翻译器并入 dispatch**：`number` / `calculator_translator` / `shijian2` /
   `input_statistics` 从独立 `lua_translator` 入口改为在 `lua/tiger_sentence_dispatch.lua`
   内顺序调用；`input_statistics` 的 `init/fini` 由 dispatch 组件代管。
   Lua 翻译器入口：**7 → 3**（dispatch、zaoci、主引擎）。
2. **历史捕获节流**：`input_statistics` 与 `tiger_kf` 不再每键调用
   `commit_history:to_table()`；只在 `commit_notifier`、输入变短（提前上屏/回删）和首帧时扫描。
   普通打字每键输入都在变长，跳过这些扫描可显著减少临时表分配。

主引擎、造词、全字集、拼音反查、混输、快符、统计功能均保留。

## 验证

- 契约 21 cases / 132 checks；完整回归 exit 0（`test_sentence_dispatch` 已适配 dispatch 新入口）。
- 功能实测：普通整句、反查 `nihao`、全字集 `\xwdk`、快符 `;a`、计算器 `=1+1`、日期 `/date`、
  统计 `//1`、提前上屏 + `;z` 整段重复均正常。
- 统计精度：提前上屏 12 字整句仍为「字数 +12、次数 +1」。

## 延迟对照（macOS，真实 librime + 插件）

同一机器、同一插件；旧接线为生产目录副本（仅还原 7 个 Lua 翻译器入口），新接线为当前代码。
