# 双拼专用反查表（小鹤已落地）

日期：2026-11-05（v0.3.26 之后）。

## 问题

双拼反查原来是「按键 → 转成全拼 → 查全拼表」。全拼表里有 **113,796 条简拼码**
（占 46%，如 `ben`=包二奶），转换失败时还要处理「残余字母怎么办」。任何兜底都会
把全拼/简拼词混进双拼候选，表现为：

- `` `bf `` 出「包二奶」（简拼码 ben 抢走「本」）
- 打错键时模型把简拼串硬拼成一句看似通顺的话（「构件安装包包二奶」）

## 方案

给双拼生成**专用反查表**：键串直接是码表的 code，只含整音节词条，没有简拼行。

```
dicts/pinyin_reverse.dict.yaml      构件   gou jian   1269
        ↓ tools/export_double_pinyin_codes.py flypy
pinyin.flypy.codes.txt              goujian<TAB>gzjm<TAB>1269
        ↓ tools/build_pinyin_codes_index.py --prefix pinyin.flypy
models/pinyin.flypy.{idx,dat,pool}
        ↓ 运行时 lua/tiger_pinyin_map.lua
输入 gzjm → 查表得 goujian → 交给现有引擎解码（引擎零改动）
```

- 表里没有的键串 = 没有候选，**不转换、不兜底**，结构上不可能“猜”。
- 全拼（`yin_qp`）继续用 `pinyin.qp.codes.txt`，行为不变。
- 索引格式与 `pinyin.codes.*` 完全相同，复用同一个 Lua 读取器。
- 缺少专用表时（测试环境/旧部署）自动退回键位转换，并保留「无简拼、禁残余兜底」过滤。

## 生成规则

- 音节 → 双拍键的唯一映射：优先两键、优先首字母与音节一致的写法
  （`an`→`an`、`ai`→`ai`、`a`→`aa`、`ju`→`ju`）。
- 同一 (键串, 全拼码) 取最大权重；行序按权重降序 = 组内 rank。
- 缺音节的词条跳过（小鹤约 1,150 条，多为 `lo`/`m` 这类特殊音节）。

## 数据

| 项目 | 数值 |
|---|---|
| 源词条（含简拼）| 247,765 |
| 双拼表条目 | **86,151**（唯一键串 86,151）|
| 索引体积 | 约 **4.2 MB**（idx 2.7 + dat 0.7 + pool 0.8）|
| 现有全拼索引 | 约 7.8 MB |
| 表内简拼行 | **0** |

## 性能

| 环节 | 耗时 |
|---|---:|
| `convert_keys`（旧路径，可省） | 0.74 µs/键 |
| 索引查询 `lookup`（新路径） | 16 µs/键 |
| 五阶模型解码（不变） | 8–14 ms/键 |

占比 < 0.2%，且表更小（4.2MB vs 7.8MB）→ 首键换页略快。

## 复现

```bash
python3 tools/export_double_pinyin_codes.py flypy
python3 tools/build_pinyin_codes_index.py --source pinyin.flypy.codes.txt \
    --prefix pinyin.flypy --out-dir models
```

其它打法（zrm/mspy/sogou）可按同样方式生成，表名 `pinyin.<scheme>.codes.txt`；
运行时按当前 `yin_scheme` 懒加载对应索引。
