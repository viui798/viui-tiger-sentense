# 更新说明：虎整句引擎升级到上游 20261007-r3

日期：2026-10-08

## 一句话

虎整句（`tiger_sentence`）的引擎升级到上游 `虎整句Rime-20261007-r3-d46fab4-完整包`（提交 `d46fab43019a49fd44223985c249a34924ab47d1`），方案名与版本、Tab 处理也对齐了上游；**中英混输、自造词、拼音反查、快符、简繁、输入统计等整合功能全部保留**。

## 1. 引擎升级

| 文件 | 变化 |
|---|---|
| `lua/tiger_sentence.lua` | 以上游 20261007-r3 为底，重新回填本仓库的整合代码（33 处、+649/−19 行） |
| `lua/tiger_sentence_correction.lua` | 与上游逐字节一致（`M.result`/`M.merge` 新增可选 `reorder` 参数） |
| `lua/tiger_sentence_learning.lua` | 与上游逐字节一致（新增 `exact-correction-v1` 系列函数） |

本版相对上一版引擎（20261001-D89-r3）的新能力：

- **正码可学习超过纠错候选**：强档输入 `ujkf` 初始菜单为「轮滑、热滑、拾滑、捡」，明确点选或用 Tab 确认「捡」一次后，下一次相同输入「捡」排在第一位，重启后保留。
- 偏好记录使用新模式 `exact-correction-v1|<基础模式>`，与原有 `sentence-v2|…`、`fusion-v1|…` 命名空间互不干扰，**学习库无需迁移**；新旧记录可以同时生效。
- 发生此类重排的一轮会清空自动上屏证据，避免沿用旧首选的成熟判断。
- 恢复提交去重：同一次选择在处理器与提交通知器里重复登记时只记一条。
- 收窄学习早退条件：只有「本次选择本身带纠错来源」才跳过学习（原先是只要涉及纠错候选就整段不学习）。

## 2. 整合功能全部保留

升级没有改动这些功能，整合代码逐字节保留：

- **中英混输**：`[` 进入英文、`]` 返回，`[西文]` / `[中文]` 提示，英文词典联想，提前上屏边界处理
- **自造词**：`` ` `` 造词并入整句词库、〔自造词〕标记、Tab 调频与降级撤销、`编码/` 删词
- **虎单/虎词同款辅助**：拼音反查、快符、拆字、emoji、Unicode 提示与编码显示、数字转大写、计算器、时间日期、输入统计、击键计数
- **简繁四档、符号菜单 `/xx`、万象标点表、全部 Ctrl 快捷键**

整合代码分布：造词 17 处、中英混输 12 处、结构性改写 5 处；逐条对照见 `docs/整合版与上游原版深度对比.md`。

## 3. 与上游的对齐项

- **方案名/版本**：`虎整句 D89-r3` / `1.5-d89-r3` → `虎整句` / `1.5`
- **Tab 处理**：改为上游方式
  - `key_binder` 增加 `Tab → Down`、`Shift+Tab → Up`
  - 处理器顺序调整为 `… recognizer → tiger_kf → tiger_sentence_processor → key_binder → speller`
  - 这两处必须同时改：若只加绑定，`key_binder` 会先吞掉 Tab 并替换成 Down，整句处理器收到的是 Down，`state.tab_pending` 永不置位，会导致 Tab 选重学习、Tab 后打字确认、段落续接判断全部失效；而 navigator 仍会移动高亮，表面上看 Tab 照常可用，不易发现。
- 快符仍排在整句处理器之前；`tiger_kf` 会跳过带修饰位的 keycode，Ctrl 组合键不受影响。
