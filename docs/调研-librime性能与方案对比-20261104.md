# 上篇：librime-octagram、grammar 接入点与 librime-lua 性能问题

## 一、librime-octagram：功能定位、模型格式、使用现状

### 1.1 功能定位

[lotem/librime-octagram](https://github.com/lotem/librime-octagram)（"RIME〖八股文〗語法插件"，BSD-3-Clause）是 librime 的 `grammar` 组件实现。它**不做组句**，只实现 `Grammar::Query(context, word, is_rear) → double`（返回罚分），供 librime 内置组句器 [poet.cc](https://github.com/rime/librime/blob/master/src/rime/gear/poet.cc) 在 beam search 扩边时调用。

### 1.2 模型格式（.gram）

源码 6 文件（`src/gram_db.cc/h`、`gram_encoding.cc/h`、`octagram.cc/h`、`grammar_module.cc`）+ [tools/build_grammar.cc](https://github.com/lotem/librime-octagram/blob/master/tools/build_grammar.cc)。格式（[gram_db.h](https://github.com/lotem/librime-octagram/blob/master/src/gram_db.h)）：

- 文件 = `Metadata{format[32]="Rime::Grammar/1.0", db_checksum, double_array_size, double_array}` + **Darts 双数组 Trie 镜像**，`MappedFile` mmap 零拷贝，运行时常驻几乎为 0。
- 值域：`log(prob) × 10000` 取整。
- 查询（[octagram.cc](https://github.com/lotem/librime-octagram/blob/master/src/octagram.cc)）：context 末尾 n 字 + word 前 n 字编码后 `commonPrefixSearch`，取前缀匹配**最大值**再叠罚分。默认参数 `collocation_max_length=4, collocation_min_length=3, collocation_penalty=-12, non_collocation_penalty=-12, weak_collocation_penalty=-24, rear_penalty=-18`。

**要点：octagram 是「搭配库」（context+word 平键值对最大值查询），不是带 backoff 链的真 n-gram**——没有回退递归、没有条件概率域、键长被 `kMaxEncodedUnicode=8` 封顶。

### 1.3 数据构建

[build_grammar.cc](https://github.com/lotem/librime-octagram/blob/master/tools/build_grammar.cc) 仅 37 行：stdin 读 `key value` 对排序建 Trie。数据仓库 [lotem/rime-octagram-data](https://github.com/lotem/rime-octagram-data)（LGPL-3.0），Release `20260712` 重制模型：`zh-hant-t-essay-bgc.gram` ≈10.3MB 字模型、`zh-hant-t-essay-bgw.gram` ≈41.4MB 词模型；hans 分支同量级。

### 1.4 谁在用

- **鼠须管官方预置**：[Squirrel CHANGELOG](https://github.com/rime/squirrel/blob/master/CHANGELOG.md)（0.18 起）安装包含 `lua`、`octagram`、`predict` 三插件与八股文语法库（傳承字）。本机实测确认三个 dylib 与 SharedSupport 下的 .gram 文件存在。[librime-octagram#2](https://github.com/lotem/librime-octagram/issues/2)：lotem 原话「鼠鬚管安裝包集成了插件和數據文件，預設方案開箱即用」。
- **现代最大用户是万象生态**：[amzxyz/RIME-LMDG](https://github.com/amzxyz/RIME-LMDG)（48GB 语料）发布 `wanxiang-lts-zh-hans.gram` **≈418MB**，[wanxiang.schema.yaml](https://github.com/amzxyz/rime-wanxiang/blob/master/wanxiang.schema.yaml) 配置 `collocation_max_length: 6` 等。训练管线 [rime-build-grammar-word-frequency](https://github.com/amzxyz/rime-build-grammar-word-frequency)。
- 效果评测：[gaboolic/rime-schema-compare](https://github.com/gaboolic/rime-schema-compare)（rime_frost 词库 + 万象语法模型：223,535 句全对 61.71%）。
- 官方**没有延迟基准**；机理上 mmap Trie 单次查询 O(键长)、无堆分配。

### 1.5 事实核查

librime master 的 [grammar.h](https://github.com/rime/librime/blob/master/src/rime/gear/grammar.h) 只有三参数 `Query`；**不存在** QueryType 枚举（全局代码搜索确认）。`Grammar` 缺位时统一罚 `kPenalty = -13.8155`。

## 二、librime 的语法模型接入点

- 组句器 [poet.cc](https://github.com/rime/librime/blob/master/src/rime/gear/poet.cc)（355 行）：`Line{predecessor, entry, end_pos, weight, text_hash}`；有 grammar 走 `BeamSearch`（每状态按 last_word 去重 top-7，`kMaxLineCandidates=7`），无 grammar 退化为 DP；权重 = 父链累计 + `Grammar::Evaluate(...)`。
- 消费者：[table_translator.cc](https://github.com/rime/librime/blob/master/src/rime/gear/table_translator.cc) `poet_->MakeSentence(graph, ...)`；script_translator 同理；跨句重打分在 [contextual_translation.cc](https://github.com/rime/librime/blob/master/src/rime/gear/contextual_translation.cc)。
- 插件注入：octagram 用 `RIME_REGISTER_MODULE` 注册模块；librime 由 [plugins_module.cc](https://github.com/rime/librime/blob/master/plugins/plugins_module.cc) 用 boost::dll 逐个 dlopen `RIME_PLUGINS_DIR`（commit [b2abd09](https://github.com/rime/librime/commit/b2abd09)，[librime#431](https://github.com/rime/librime/issues/431)）。

### 「C++ grammar 插件」vs「Lua translator 自建 lattice」

| 维度 | octagram 式 C++ grammar | Lua translator 自建 lattice（虎整句做法） |
|---|---|---|
| 得分模型 | 搭配最大值+常数罚分，**表达不了 Kneser-Ney bow 回退链**；只打分不生成候选 | 完全自主：自建词库/解码/beam/五阶评分/排序 |
| 内存 | mmap 零拷贝、不进 GC 堆 | 全部缓存是 Lua 对象，放大每次 full GC 扫描成本 |
| Lua 接入 | **librime-lua 无 grammar 绑定**（[#105](https://github.com/hchunhui/librime-lua/issues/105) open） | 无需 C++ |
| 社区证据 | RIME-LMDG README：「这与所谓的智能模型完全不同，即消耗算力，又不能用于翻译器阶段」 | [rime-ice#1150](https://github.com/iDvel/rime-ice/issues/1150)：lua「可能会确实会影响性能和卡顿」 |

## 三、迁移可行性判断（TCSKNM03 → C++）

### 3.1 「转格式」不可行

TCSKNM03（405,663,171 B）是字符级五阶模型：256B 头 + 词表 + 2~5 阶 256 桶目录/块索引/后继记录，**Kneser-Ney 依赖 bow 链回退**（`tiger_sentence_fivegram.lua` 的 `score_history`）。octagram 的扁平键值结构没有 backoff 位、`Query` 语义是前缀匹配取最大、键长 ≤8 字——展平会丢回退链且键空间爆炸（418MB 万象 gram 也只覆盖 ≤6 字搭配）。反向：Poet 只对 table 词典的 WordGraph 打分，虎整句是 24.8 万条自建码表 + 自管 beam——等于重写整个 translator。

### 3.2 「C++ 重写 reader」可行但暂不做

可行面：`tiger_sentence_fivegram.lua` 仅 373 行（头解析、Q8 解码、二分索引、8MiB 页缓存、16k/32k 缓存），C++ mmap 版约 600-800 行，解码部分可压到亚毫秒。
不划算：①**瓶颈错位**——实测主导项是 librime-lua 析构全量 GC（本机归因 19/29ms 慢键），上游 [#431](https://github.com/hchunhui/librime-lua/pull/431) 已修（2026-05 合并）而本机 Squirrel 1.1.2（2026-01-14 构建）未受益；②分发受限（官方不带第三方 dylib、移动端插件编译进 App、Lua 版必须双轨维护）；③若走 C++ translator 整替，涉及主 chunk 全部集成点（200 local 上限即风险信号）。

### 3.3 结论

整体迁移/转格式：**不可行**。只重写 reader：**技术可行、暂不做**（升级运行时后最大动机解除）。未来若做，形态应是完整 C++ translator 插件，而非单独 LM reader。

# 下篇：优秀方案引擎链对比（雾凇 / 万象系 / 形码方案）

## 一、雾凇拼音（iDvel/rime-ice）

- 链路：1 个 lua_processor；emoji/简繁全部 OpenCC simplifier（C++）；7 个 lua_filter + reverse_lookup_filter + 2 simplifier + uniquifier；lua_translator 含 [force_gc.lua](https://github.com/iDvel/rime-ice/blob/main/lua/force_gc.lua)（每词组 `collectgarbage("step")`，直接引用 librime-lua#307）。
- opencc 目录全是**预编译 .ocd2**。
- [rime-ice#1150](https://github.com/iDvel/rime-ice/issues/1150)：确认 librime-lua 两个严重 bug（Squirrel 内存泄漏、同步失效）已修；作者结论「不建议大量使用 lua 实现某些功能」；[#850](https://github.com/iDvel/rime-ice/issues/850) Squirrel 18.0 内存泄漏。
- [Dvel 笔记](https://dvel.me/posts/rime-ice)：**「开启简拼 + 过多英文单词会导致打字极其卡顿」——speller/algebra 的 derive 量决定 prism 体积与查表负担**。

## 二、万象系（amzxyz）

- [rime_wanxiang](https://github.com/amzxyz/rime_wanxiang) + [RIME-LMDG](https://github.com/amzxyz/RIME-LMDG)（octagram 格式、mmap、句准 76.86% vs 无模型 62.34%）；版本分层 = 性能分层：**Pro / Lite（裁预测）/ Pure（零 Lua）**。
- engine：8 lua_processor、7 lua_translator、~15 lua_filter + 4 simplifier——Lua 比雾凇重得多；grammar 配置 `collocation_max_length: 6` 等。
- 三个工程手法：①注释下放单个滤镜（`spelling_hints: 30` + `super_comment_preedit` 统一渲染）；②super_replacer 部署期预编译 LevelDB（芝士虎整已用）；③字符集过滤用预编译 `charset.reverse.bin`。
- **官方性能剖面** [profile-analysis.md](https://github.com/amzxyz/rime_wanxiang/blob/main/docs/doc/profile-analysis.md)（1,997 键）：
  - P50 **479μs**、P99 36ms；**TransSeg 占 Compose 98%**，Menu 0.1%——分词菜单不值得优化；
  - 最大单项：script_translator 1,397μs/次、user_dict_set（LevelDB 写）977μs/次；
  - **Lua 仅占 16%，C++ 词典 I/O 占 84%——「瓶颈不在 Lua」**；
  - lua_translator 每次组词都被调用（即使没触发），7 个各 43-330μs × 813 次；
  - 滤镜链串行：第一个滤镜要等最后 9 个 yield 完；
  - OpenCC simplifier + uniquifier 合计 **2μs/次**，比最便宜 Lua 滤镜（55μs）便宜一个量级。

## 三、其他形码方案

- **白霜**（[rime-frost](https://github.com/gaboolic/rime-frost)）：形码关 completion/user_dict/sentence/encoder；**拆字注释用 `simplifier@chaifen`**（`moqi_chaifen.json`）；opencc 全 .ocd2；AUR 连 build/ 预编译产物分发。
- **胖虎**（[rime-tiger](https://github.com/N5NS/rime-tiger)）：`__include` 模块化拼装 7 个方案；octagram 参数最激进（`collocation_max_length: 2`、`max_homophones: 1`、`max_homographs: 1`、`contextual_suggestions: true`）；`octagram/disable: __patch: grammar: {}` 一行关模型。
- **万象虎**（[wxzhh](https://github.com/zhhwux/wxzhh)）：造词 translator `db_class: tabledb`（文本用户词典，无 LevelDB 写放大）。
- 事故教训：[aux-code#18](https://github.com/HowcanoeWang/rime-lua-aux-code/issues/18)（env 挂大表 + 无短路遍历 → 112MB；修复后 30MB）；[fcitx5-android#532](https://github.com/fcitx5-android/fcitx5-android/issues/532)（>30MB 词库首键慢，走 table.bin mmap 无此问题）；[librime-lua#335](https://github.com/hchunhui/librime-lua/issues/335)（Memory 对象 bug 致同步失效）。

## 四、librime 性能旋钮汇总

| 旋钮 | 机制 | 佐证 |
|---|---|---|
| speller/algebra 派生量 | derive/abbrev 全部部署期展开进 prism，越多越大越贵 | Dvel 笔记、[rime/home#514](https://github.com/rime/home/issues/514) |
| enable_completion | 前缀补全是运行时持续成本，形码普遍关 | 白霜/胖虎 |
| userdb（LevelDB） | 每提交 ~1ms（WAL+memtable）；tabledb 零写 | 万象剖面、[rime 讨论#1959](https://github.com/orgs/rime/discussions/1959) |
| contextual_suggestions | 开了才让模型参与 translator 调频 | 万象/胖虎 |
| max_homophones / max_homographs | 限制参与模型评分的同音/同形数 | 胖虎 |
| __patch 深度 | 只影响部署期，不影响每键 | build 产物机制 |
| OpenCC .ocd2 | 预编译二进制 vs 运行时 txt | 雾凇/白霜 |
| Lua 大数据 | 挂 env 每会话一份 + 无短路 = 内存翻倍；应模块级 + 早短路 | aux-code#18 |
| Lua 候选缓冲 | 缓冲候选的滤镜必须主动 GC | librime-lua#307、force_gc |
