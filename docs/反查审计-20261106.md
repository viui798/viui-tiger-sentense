# 反查系统四特性深度审计（2026-11-06）

> 对照用户需求的四个特性逐条实测（真实 librime 无头探针 `tools/fancha_probe.cpp`，
> 隔离目录 = v0.3.26-6 工作区克隆），GitHub 社区调研并行。**本轮不改任何方案文件**，
> 全部结论与提案记录在案。原始用例与输出见 `docs/反查审计数据-20261106/`。

**总评：四个特性里 ②③④ 已达用户描述（②③全部示例 top1，④生产路径双模式隔离+
简拼边界全对）；真正的缺口集中在 ①调频的两个点（MRU 语义、首查命中死锁），
外加两处引擎层小债。方案架构无需改动。**

## 一、四特性记分卡（全部用例实测）

### 特性 1：正常反查 + 同音调频 —— **大部分达成，两处缺口**

| 用例 | 实测 | 判定 |
|---|---|---|
| `` `fjia `` | 反查 **top1**（反差/梵刹随其后） | ✅ |
| `` `vsgo `` | 中国 **top1** | ✅ |
| `` `gx `` | 寡在第 **5** 位（挂瓜刮罖寡），18 候选 | ⚠️ 首查不置顶 |
| `` `fu `` | 覆 **前 20 个候选都没有**（服复富府福负…） | ❌ 见缺口 B |

- **调频记录在生产环境正常**：真机 `~/Library/Rime/reverse_freq.txt` 存在
  （寡×1、遍×3、终幕×2、便携、觊觎、潜伏、即用……2026-11-05 23:15）——
  用户选过的「寡」已置顶，与需求一致。无头测试台跑不了 lua_processor 的
  init 钩子（commit 通知器不连），调频行为无法在探针内复现，以真机数据为准。
- **缺口 A（MRU 语义）**：`reverse_freq.lua` 的排序是「次数降序，同次数回退
  原始菜单序」（`rank()`，reverse_freq.lua:81-101）。用户要的是**最近优先栈**：
  「第一次选 A（升首）、第二次选 B（B 一选、A 二选）」。当前实现下 B、A 同为
  1 次时 A（原序在前）仍排前面。真机数据「遍×3」说明次数确实在累积，
  但语义与需求有偏差。
- **缺口 B（首查死锁）**：`覆` 在 fu 组排位 **23**（组共 199 条），而反查菜单
  上限 20 条（引擎 `candidate_limit`）——**排位 21~32 的常用字在纯反查里不可见**；
  看不见就选不了、选不了就永远不进调频——死锁。词库数据本身没问题
  （覆 在表内，组内 199 条全量在索引），纯粹是菜单窗口太小。

### 特性 2：以字定词（模型组词）—— **完全达成，全部 top1**

| 用例 | 实测 |
|---|---|
| `` `cd`xu`ky `` | 蔡徐坤 **top1**（蔡旭坤/蔡徐昆 2、3——模型在同音竞争） |
| `` `yi`yh`qm`xi `` | 易烊千玺 **top1**（易烊千禧 2） |
| `` `yici`lwtv `` | 以此类推 **top1**（依次类推/以次类推 2、3） |
| `` `uuru`fa `` | 输入法 **top1** |

批量测试 38 词（30 词库内单块 + 8 词库外逐字块）：**top1 命中 37，1 例为
测试键串自错**（引擎还把它优雅解成 `yin+le` 的「因了」）。唯一真实的
非 top1 是「芝士虎整」输给同音「只是虎整」——同音竞争，选一次即被调频
固化（真机数据里已有同类记录）。**社区调研结论：这套「反查块 + 五阶模型
现场组词」在社区没有同款，是领先实现。**

### 特性 3：混输不落句 —— **完全达成，全部 top1**

| 用例 | 实测 |
|---|---|
| `be`jidubeuegmmup`（虎码+反查块+虎码） | 她嫉妒她的美貌 **top1** |
| `j;\`iimwwhllbtmzaqocbhub\`sy\`wu\`ks`（长混输 3 反查块） | 什么魑魅魍魉妖魔都不怕孙悟空 **top1** |
| `` `fugdyf`hzhzuemd`mmbw ``（反查块开头混虎码） | 覆盖上厚厚的大棉被 **top1** |

句首/句中/句尾、单块多块、纯反查块开头混虎码——全部一次到位。
混输候选也接入了调频（`tiger_sentence_pinyin.lua:320-329`，v0.3.25 补齐）。

### 特性 4：全拼/双拼隔离 —— **达成（生产路径验证）**

| 用例（`/pinyin` 切换后） | 实测 |
|---|---|
| `` `/pinyin\`fan\`cha `` | 翻查/反查/反差 ✓（全拼多音节带内部标记） |
| `` `/pinyin\`jsj `` | 计算机 **top1** ✓ 全拼简拼可用 |
| `` `/pinyin\`nh `` | 你好 **top1** ✓ 2 键简拼可用 |
| `` `/pinyin\`fjia `` | **0 候选** ✓ 双拼键串在全拼模式正确失效 |
| `` `/flypy\`jsj `` | **0 候选** ✓ 双拼无简拼 |
| `` `/flypy\`bm `` | 变/便/边 ✓ 无「比按」全拼泄漏 |

隔离机制 = 双拼专用反查表（`tiger_pinyin_map.lua` 精确查表无兜底）+
引擎侧简拼门（`set_strict_abbreviation`/`set_allow_abbreviation_edges`）。
社区对照：官方双拼方案用「编译期不加 abbrev」实现禁简拼，本方案用
运行期门禁——效果等价，且比社区常见的 algebra derive 混输路线
（Dvel 博客确认那是串台来源）更严格。
**审计注意事项：测试时必须用 `/pinyin` `/flypy` 生产命令切换打法；
直接 set_option 会被 options.yaml 的持久化重放覆盖（探针踩坑，见 §五）。**

## 二、缺口与优化提案（按优先级）

### P1 · 调频升级为 MRU 栈（特性 1 的核心诉求）

`reverse_freq.txt` 行格式扩展：`code<TAB>词<TAB>次数<TAB>最近序号`。
排序改为：有过记录的按「最近序号」降序（最近选的一选，上次选的二选），
未选过的按模型序。格式向后兼容（旧行缺省序号按次数）。
社区调研确认**没有现成 MRU 实现**（最接近的是手动置顶/调序：万象 slim 的
Ctrl+P、胖虎的 📌、wxzhh 的 seq_words.lua），需要自己写——量级约 30 行。
落盘卫生可借鉴 [rime-context-filter](https://github.com/sakuradairong/rime-context-filter)：
原子写（已有 tmp+rename ✓）、间隔落盘（当前每次选择即写，移动端可改计数触发）。

### P2 · 反查首查死锁破解（`fu→覆` 类）

三个可选方案（可组合）：
1. **反查段放宽菜单上限**：短反查段（≤8 字母）把 `candidate_limit` 从 20
   放宽到 50（引擎加一个 setter，反查实例专用）——一行级改动，直接让
   排位 21~50 的字可见可翻页。
2. **辅助码缩窄**：zi.pro 本就带形辅码（`;dz` 类），反查表把「音节+辅码」
   作为缩窄键即可精确到字——但当前交互未定义辅码键（` 后面直接打辅码会
   与音节冲突），需要设计输入语法，量级中等。
3. **调频引导词覆盖**：`fugai→覆盖` 选过之后，把「覆盖」的首字「覆」同时
   记一条 `fu→覆` 的引导记录（选词顺带提升其组成字）——用户打 `fu 时 覆
   直升首位。实现小（record 时拆词首字额外记一条），体感收益大。
   **推荐 1+3 组合**：1 解决可见性，3 解决常用性。

### P3 · 引擎层小债（顺手修）

1. **`tiger_mixed.lua:364` 死变量**：`if not has_literal and leading_pinyin == false`
   ——`leading_pinyin` 从未定义（恒 nil），条件恒假，整句等同
   `if not has_literal then return nil`。与 345 行的 first_block 放弃逻辑叠加后，
   「段首块解析失败」的意图语义需要人工核对一次，消除误导。
2. **QP 带内部标记的解码为空**：第二实例 `decode("fan\`cha")` 直接空
   （`decode("fancha")` 正常；双拼键串的标记解码反而正常）。当前靠
   build_overlay 兜底出候选（功能没坏，多一轮回退），引擎的音节标记
   分段对全拼键串的适配值得查一次。

### P4 · 建议（调研引入，非缺陷）

1. **以字定词落词库闭环**：连续反查块上屏成词后，走 `zaoci_bridge` 自动
   落词库（对标万象笔画造词），词库外词第二次直接整词打出。调研确认
   「先模型现场组、后落库固化」是社区接受度最高的路径。
2. **契约测试补反查用例**：把本轮实测的四特性用例（含全拼/双拼串台断言、
   简拼边界）固化进 `tools/test_fancha_contract.lua`，防止后续改动回退。
3. **长期对标 wxzhh**（zhhwux/wxzhh，同为虎码+万象模型+三入口反查）：
   其修复日志（1/2 码音码字顶屏、句中聚拢等）是现成的反例清单。

## 三、词库适配性结论

- 反查码表覆盖充分：fu 组 199 条全量在索引（无 32 截断——截断发生在
  菜单层不在数据层）；38 词批量首查 92%+；词库外词靠模型组句全部命中。
- 词库对四特性**完全适配**，不需要动词库；缺口全部在交互层（菜单窗口、
  排序语义）。

## 四、测试台注意事项（复跑必读）

1. 打法切换必须用生产命令 `/pinyin` `/flypy`（探针内当按键输入）；
   直接 `set_option` 会被 `tiger_sentence.options.yaml` 的持久化重放覆盖
   （v0.3.26 的选项生命周期由 dispatch 世代管理，headless 下 M.options 的
   init/sync 不运行——探针内验证过零命中）。
2. lua_processor 的 init 钩子（reverse_freq 的 commit 通知器连接）在无头
   探针内不触发——调频行为无法 headless 复现，以真机 reverse_freq.txt
   数据为准。
3. 复跑：`g++ tools/fancha_probe.cpp`（链接鼠须管 librime，见文件头）+
   `docs/反查审计数据-20261106/` 内的 case 文件。
