## 3. 关键决策记录

### D1｜移除中英混输（v0.2.8.2）

- **背景**：混输在手机端一旦使用，之后普通中文输入持续变卡，切换方案也不恢复。
- **决策**：整体摘除混输（`[`/`]` 恢复直接上屏半角括号），保留其余辅助功能。
- **影响**：`lua/tiger_sentence.lua` 净减约 610 行；`dicts/en.dict.yaml`、`lua/data/english_chinese.txt`、
  `lua/db.lua` 的 en_dict 建库一并删除。README/说明标注「已于 v0.2.8.2 移除」。

### D2｜性能治理（v0.2.8.1 / v0.2.8.3）

- 击键计数 pending 改纯内存、取消每键同步写盘；统计落盘 ≥30s 节流。
- 简繁滤镜 `max_lookahead` 可配（默认 16，低配 8），`fmm_cache` 加上限。
- 重码组句加 `MAX_DFS_NODES=2000` 硬上限。
- 停用英文表 init 预热（方案加载不再为已移除功能付费，省 ~158ms / ~6MB）。

### D3｜v0.2.10 整体回退到 v0.2.9（2026-10-24）

- **决策**：用户要求删掉 v0.2.10 整个版本，回到 v0.2.9。
- **执行**：删 Release + 标签；`git reset --hard af46541` 后强推；`~/Library/Rime` 用 v0.2.9 包覆盖并重新部署；
  桌面 v0.2.10 包移入废纸篓。
- **注意**：当时没有保留备份分支。若未来要恢复，见上方时间线的 reflog 提交。

### D4｜升级上游 1.6.20261030.1 的四个口径（v0.3.0）

按用户要求，全部**按上游标准**：

1. 字集默认「常用」（生僻字需 `Ctrl+J` 切全字集）；
2. 回删默认「整字」；
3. 首次 Tab 选第二项（`first_choice_selection=false`，不锁定/不强化）；
4. `ascii_component` 保留（v0.3.1 进一步接线，见 D6）。

### D5｜`Ctrl+J` 冲突处理（v0.3.0）

- 上游用 `Ctrl+J` 切字集，且字集处理器排在 `key_binder` 之前。
- 本仓库原本 `Ctrl+J` 是拆字注释 → **虎整句的拆字改为 `Ctrl+Shift+J`**，虎单/虎词不变。
- 已写入 `tiger_sentence.schema.yaml` 的 key_binder 注释与用户文档。

### D6｜ascii 处理器与上游接线（v0.3.1）

- 本仓库在 v0.2.8.2 曾换回原生 `ascii_composer`；但上游的 `lua_processor@tiger_sentence_ascii`
  负责「buffered（提前上屏至编码）状态下切西文时提交显示候选，而不是内部 `~` 标记」。
- 用户要求「上游有的必须有」→ v0.3.1 换回上游处理器，并在 `rime.lua` 注册
  `tiger_sentence_ascii = tiger_sentence.ascii_component`。

### D7｜Lua 200 局部变量上限

- 合并上游 20261030 后主 chunk 局部变量超限（报 `too many local variables`）。
- 解决：`zaoci_bridge` 与 `correction_mark_state` 改为全局表；功能不变。
- **后续新增功能不要再加文件级 `local`。**

### D8｜测试对齐上游（v0.3.1）

- 上游不提供测试；历史测试停留在 20261009 语义，导致套件长期红。
- 判定方法：用**纯净上游模块**跑同一条用例（`TIGER_SENTENCE_MODULE=...`）。
  上游也失败 → 测试过期，按当前行为改写；上游通过 → 我们的问题。
- 已处理：learning（码长门槛、结果级 `learning_affected`、删除 fusion/exact 覆盖）、
  lexical prior（单候选跳过重排）、backspace（显式选「回删编码」）、allocation（删除 fusion 用例）。
- 结果：`tools/run_regressions.py` 全绿。

### D9｜移除性能打点（v0.3.1）

- `perf_diag` / `tiger_sentence/perf_log` 是 2026-10-11 为定位手机卡顿加的临时诊断，默认关闭。
- 用户要求清理 → 移除；历史说明 `docs/更新说明-20261011-统计与滤镜性能修复.md` 顶部已注明。

### D10｜辅助开关跨会话记忆（v0.3.2，2026-10-31）

- **现象**：虎整句的拆隐/拆显、拼音注释、emoji、U 区/U 编、音码等开关，切换后只对当前输入会话有效；
  换应用、重启或重新部署就回默认，而「提前上屏」却能全局生效。
- **根因**：librime 每个输入会话都新建一个 `Engine`（`Session::Session()`），引擎构造时
  `RestoreSavedOptions()` 只恢复 `switcher/save_options` 里的项，随后 `InitializeOptions()`
  把 `switches` 中带 `reset` 的开关**强制**写回 reset 值——`reset` 是「每会话复位」，不是「首次默认」。
  同时 `key_binder` 的 `toggle:` 只改内存选项，从不写 `user.yaml`；只有方案菜单里的开关才会落盘。
- **决策**：与「提前上屏」一致，用方案自己的 Rime Config 保存偏好：
  - 虎整句：扩展 `lua/tiger_sentence.lua` 的 `M.options`（`tiger_sentence.options.yaml`），
    含 radio 组按「选中档 option 名」保存（`options/tiger_sentence_hans`、`.../tiger_sentence_yin_scheme`）；
  - 虎单/虎词：新增 `lua/option_persist.lua`（`tiger.options.yaml` / `tigress.options.yaml`），
    注册为 `lua_processor@*option_persist`。
- **硬约束**：凡是「要记住」的开关一律**不写 reset**。Lua 组件的 init 发生在 `InitializeComponents()`，
  而 `InitializeOptions()` 在其之后执行；留着 reset 会把刚恢复的偏好覆盖掉（已用真实 librime 探针复现）。
- **保留 reset**：`ascii_mode`、`ascii_punct`、`full_shape` 仍按 Rime 惯例每会话复位。
- **附带修复**：`yin`（Ctrl+Q 音码开关）在三个方案里原本没有任何消费者；现在由 `lua/yin_pick.lua`
  读取，关闭后不再做反查 tag 转换，单引号前缀不再出拼音候选。

## 4. 架构与数据流

### 4.1 方案与依赖

```
default.custom.yaml → schema_list: tiger / tigress / tiger_sentence / wanxiang_pro
tiger_sentence.schema.yaml
  dependencies: tigress（造词检索）、kf（快符）、tiger_lookup（拆字）、
                wanxiang_pro_qp/zrm/mspy/sogou（反查拼写索引）
```

### 4.2 虎整句处理器顺序（整合版）

```
lua_processor@*set_schema      # /flypy /pinyin /zrm /mspy /sogou
lua_processor@tiger_zaoci_processor
lua_processor@*key_counter
lua_processor@*shift_upper      # 中文态 Shift+字母 → 大写直出
lua_processor@tiger_sentence_ascii   # 上游同款（buffered 下切西文提交显示候选）
recognizer
lua_processor@*tiger_kf         # 快符 ;a
lua_processor@tiger_sentence_processor   # 整句核心（解码、Tab、回删、字集）
key_binder
speller → punctuator → lua_processor@exe_processor → selector → navigator → express_editor
```

段/翻译/滤镜：反查 5 种打法（`yin_*`）、造词（`zaoci`）、符号菜单（`punct`）、
快符（`kf`）、计算器、时间日期、统计；滤镜含 `db`（重码替换）、`chaifen`、`emoji_cn`、
Unicode 提示/编码、`charset_filter`（字集联动）、`super_replacer`（简繁四档）、`uniquifier`。

### 4.3 虎整句引擎内部

- **码表**：`tiger_sentence.codes.txt`（15,374 条）、`char_ranks.txt`（20,000 字频）、
  `full_code_whitelist.txt`（126 字）、`supplement.txt`、`common_characters.txt`（9,770 字，字集）
  都是明文，运行时加载，不走 Rime 词典。
- **模型**：五阶 Kneser-Ney，分页加载（`sentence-fivegram-mobile.bin`）。
- **学习**：`tiger_sentence_learning.lua`（内存索引）+ `tiger_sentence_learning_text.lua`
  （文本 journal，用户目录 `自学习-tiger_sentence.txt`）；`tiger_sentence.options.yaml` 存开关。
- **本地集成点**（与上游的差异集中处）：
  - `zaoci_bridge`：造词条目参与组句/调频（`dict_first` 保持词典 rank、用户词 rank 1、
    `user_version` 触发重建、Tab 降级）。
  - `correction_mark_state`：纠错注释符号（默认 ✨，可用 `tiger_sentence/correction_mark` 覆盖）。
  - 全局表承载：绕开 Lua 200 local 上限。

### 4.4 本地独立模块

| 文件 | 功能 |
|---|---|
| `lua/shift_upper.lua` | 中文态 Shift+字母 → 直接上屏大写（兼容 `Shift+a`/`A`/裸 `Shift_L`） |
| `lua/tiger_symbol_select.lua` | 虎单/虎词：候选不足时 `;`/`'` 顶字并补标点 |
| `lua/tiger_zaoci.lua` | 反引号造词、`/` 删词、内存词库 |
| `lua/input_statistics.lua` / `key_counter.lua` | 输入统计与击键计数 |
| `lua/wanxiang/super_replacer.lua` 等 | 简繁四档、字集联动、反查 |
| `lua/set_schema.lua` | `/flypy` 等命令切反查打法 |
| `lua/tiger_kf.lua` | 快符 `;a` 立即上屏 |

## 5. 与上游的关系

### 5.1 覆盖审计（每次升级上游后必做）

比对上游 schema 与本地 schema：

- `switches`（按 `name` 或 `options` 元组）
- `engine.processors / segmentors / translators / filters`（逐项）
- `key_binder.bindings`
- `tiger_sentence.*` 配置键（含 `option_defaults` 子键）
- `menu`、`ascii_composer`
- 上游 Lua 的 `M.*` 导出（`grep -oE "^M\.[a-zA-Z_]+"`）

要求：**上游有的项必须全部存在**（本地可多，不可少）。

### 5.2 当前有意差异（v0.3.1）

文件级：29 个上游文件里 **24 个逐字节一致**；5 个不同：

| 文件 | 差异 |
|---|---|
| `tiger_sentence.schema.yaml` | 整合版：多 8 组 switches、5 个 processors、8 个 segmentors、8 个 translators、9 个 filters、额外配置块（kf/zaoci/pinyin/chaifen/emoji/charset/super_replacer…） |
| `lua/tiger_sentence.lua` | 本地集成：zaoci 桥接、用户词排序、✨ 注释、全局表 |
| `default.custom.yaml` | 本仓库的方案列表、`Ctrl+grave` 热键、`save_options` |
| `rime.lua` | 本仓库的模块注册 |
| `symbols.yaml` | 40KB 万象标点表（上游 1.5KB 精简版） |

值级差异（有意扩展，勿改回上游）：

| 键 | 上游 | 本仓库 | 原因 |
|---|---|---|---|
| `speller.alphabet` | 无 `/` | 含 `/` | 统计指令 `//1`、符号菜单 |
| `speller.delimiter` | 空格 | 空格 + `'` | 拼音反查 |
| `speller.auto_select` | false | true | 快符 `;a` 立即上屏 |

### 5.3 上游同步步骤

1. 解压上游完整包到 `/tmp`；以 `RELEASE.json` 的旧 `source_commit` 对应包为 base。
2. `git merge-file -p --diff3 ours base theirs > merged`（逐文件）。
3. 冲突时保留本地集成点（D7/D8 所述）。
4. schema 只增量：新增 switches/配置键，保留 engine/speller/recognizer/key_binder。
5. 拷入新 Lua 模块与数据文件；更新 `RELEASE.json`。
6. 跑覆盖审计（§5.1）+ 全部测试。
7. 更新 CHANGELOG、bump 版本、打包、部署、发 Release。

  `TIGER_SENTENCE_MODULE=/tmp/up/lua/tiger_sentence.lua LUA_PATH="/tmp/up/lua/?.lua;./lua/?.lua;;" lua tools/test_xxx.lua .`

### 6.2 打包

```bash
python3 tools/make_release_zip.py vX.Y.Z /tmp/cheese-tiger-vX.Y.Z.zip
```

规则（脚本内定义）：以 git ref 的文件清单为准；LFS 模型从工作区取真实文件；排除
`tools/ sync/ validation/ 手机精简版/`、`RELEASE.json`、`SHA256SUMS.txt`、`SOURCE_BASELINE.md`、
`RIME_CORRECTNESS.md`、`IOS_TEST_README.md`；生成《安装说明.txt》；写 UTF-8 标志位；输出 `.sha256`。

### 6.3 部署（macOS 鼠须管）


## 7. 已知问题与注意事项

| 项 | 说明 |
|---|---|
| 上游无测试 | 用纯净上游模块做 oracle（§5.1 / §6.1） |
| fusion / exact-correction 覆盖 | 上游 20261010 移除硬排序，本地测试随之删除，仅保留「旧记录被忽略」断言 |
| LFS 克隆 | 未安装 Git LFS 时模型是指针；`git lfs pull` 或直接用 Release 包 |
| 200 local 上限 | 新增文件级 `local` 会编译失败 |
| `squirrel.custom.yaml` | 个人配置，被 `.gitignore` 排除，不属于方案包 |
| 中文文件名 | 必须用打包脚本，手写 `zip` 会在 Windows 上乱码 |
| 手机精简词库 | `手机精简版/` 只在仓库里，不进发行包 |
| 测试夹具 | 直接在仓库根跑 `test_lexical_prior.lua` 会生成 `sentence-fivegram-mobile.bin`（已 gitignore） |

## 8. 交接检查清单（新 agent 前 30 分钟）

1. 读 `AGENTS.md` 与本文。
2. `git log --oneline -20`、`git tag --sort=-creatordate`、`gh release list` 确认版本状态。
3. 跑契约测试 + 完整回归，确认基线是绿的。
4. 核对 `RELEASE.json`（上游版本/commit/模型哈希）与 `tiger_sentence.schema.yaml` 的 `schema.version`。
5. 需要动本机输入法时：先备份 `~/Library/Rime`。
6. 任何上游升级：先做 §5.1 覆盖审计，再改代码。

## 9. 变更纪律

- 提交信息用中文，前缀表达类型：`功能：` / `修复：` / `清理：` / `文档：` / `测试：` / `发行：`。
- 每个版本：更新 `CHANGELOG.md`（新增/行为变化/验证），打附注标签，发 Release 并附 zip + sha256。
- 用户可见的行为变化（默认值、快捷键）必须同时更新 `README.md` 与 `芝士虎整说明.md`。
- 不重排大文件；不整文件覆盖整合 schema；不为「顺手」改动无关代码。
