## 3. 关键决策记录

### D1｜移除中英混输（v0.2.8.2）

- **背景**：混输在手机端一旦使用，之后普通中文输入持续变卡，切换方案也不恢复。
- **决策**：整体摘除混输（`[`/`]` 恢复直接上屏半角括号），保留其余辅助功能。
- **影响**：`lua/tiger_sentence.lua` 净减约 610 行；`dicts/en.dict.yaml`、`lua/data/english_chinese.txt`、
  `lua/db.lua` 的 en_dict 建库一并删除。README/说明标注「已于 v0.2.8.2 移除」。

### D2｜性能治理（v0.2.8.1 / v0.2.8.3）

- 击键计数 pending 改纯内存、取消每键同步写盘；统计落盘 ≥30s 节流。
- 简繁滤镜 `max_lookahead` 可配（默认 16，低配 8），`fmm_cache` 加上限。
- 重码组句加 `MAX_DFS_NODES=2000` 硬上限。
- 停用英文表 init 预热（方案加载不再为已移除功能付费，省 ~158ms / ~6MB）。

### D10｜辅助开关跨会话记忆（v0.3.2，2026-10-31）

- **现象**：虎整句的拆隐/拆显、拼音注释、emoji、U 区/U 编、音码等开关，切换后只对当前输入会话有效；
  换应用、重启或重新部署就回默认，而「提前上屏」却能全局生效。
- **根因**：librime 每个输入会话都新建一个 `Engine`（`Session::Session()`），引擎构造时
  `RestoreSavedOptions()` 只恢复 `switcher/save_options` 里的项，随后 `InitializeOptions()`
  把 `switches` 中带 `reset` 的开关**强制**写回 reset 值——`reset` 是「每会话复位」，不是「首次默认」。
  同时 `key_binder` 的 `toggle:` 只改内存选项，从不写 `user.yaml`；只有方案菜单里的开关才会落盘。
- **决策**：与「提前上屏」一致，用方案自己的 Rime Config 保存偏好：
  - 虎整句：扩展 `lua/tiger_sentence.lua` 的 `M.options`（`tiger_sentence.options.yaml`），
    含 radio 组按「选中档 option 名」保存（`options/tiger_sentence_hans`、`.../tiger_sentence_yin_scheme`）；
  - 虎单/虎词：新增 `lua/option_persist.lua`（`tiger.options.yaml` / `tigress.options.yaml`），
    注册为 `lua_processor@*option_persist`。
- **硬约束**：凡是「要记住」的开关一律**不写 reset**。Lua 组件的 init 发生在 `InitializeComponents()`，
  而 `InitializeOptions()` 在其之后执行；留着 reset 会把刚恢复的偏好覆盖掉（已用真实 librime 探针复现）。
- **保留 reset**：`ascii_mode`、`ascii_punct`、`full_shape` 仍按 Rime 惯例每会话复位。
- **附带修复**：`yin`（Ctrl+Q 音码开关）在三个方案里原本没有任何消费者；现在由 `lua/yin_pick.lua`
  读取，关闭后不再做反查 tag 转换，单引号前缀不再出拼音候选。

### D11｜反查码表分页索引与词库调整（v0.3.3）

- **现象**：v0.4.0 反查每键约 1.1 秒，且用过反查后虎码主路径也变慢。
- **定位**：`sample` 采样显示耗时在 `LuaTranslation::~LuaTranslation → Lua::gc() → luaC_fullgc`；
  反查第二实例把 43 万条码表建成 Lua 小表（常驻 ~209 MiB），全量 GC 成本随存活对象数增长。
  模型不是元凶：建库前 Lua 堆仅 11 MiB。
- **方案**：码表预编译为 `models/pinyin.codes.idx/.dat/.pool`，运行期只读三个大字符串，
  按 code 二分查找、按段取数 + 4096 条缓存（`lua/tiger_sentence_pinyin_index.lua`）。
- **词库**：换成 `dicts/pinyin_reverse.dict.yaml`（13.4 万词条，第三方拼音词库），
  导出 24.8 万条（全拼 + 多字词简拼），**不再导出辅助码**（用户明确不需要）。
- **取舍**：每键 ~20ms；长尾词覆盖少于旧 43 万条；`shuijiao` 首选变为「水饺」；
  简拼只在全拼可用（双拼码位冲突）。
- **前缀调整**：反查改为 `` ` `` 前缀、造词改为 `'` 前缀；「拼音+`` ` ``」后缀式反查暂时移除，
  `db.lua` 的尾随反引号拦截一并删除。三个 schema 的 recognizer / affix 配置同步修改。
- **回退**：v0.4.0 的整段提交不再作为发布版本，标签/Release 以 v0.3.3 替代。

### D12｜反查简拼按打法区分 + 混输不接管反查段（v0.3.14，2026-11-02）

- **现象（用户）**：双拼反查 `` `fjia `` 出现「发内存哈」；`` `fj`ia ``（1 个音节标记）候选很少；
  反查列表末尾出现「一个盘」。
- **根因 1**：码表把多字词的「首字母简拼」（`nc`=内存、`yg`=一个）当普通边参与长输入内部分词，
  `fancha` → fa+nc+ha。修复：码表第三列 `A` 标记简拼（索引 flags bit2），引擎按打法决定是否允许：
  **全拼保留**（`` `fancha `` 可以是 fa+nc+ha），**双拼关闭**（`fjia` 只出音节组合）。
- **根因 2**：音节标记展开阈值是「内部 `` ` `` ≥2」，两字词只有一个音节边界，永远不展开。
  修复：≥1 个内部 `` ` `` 即展开（末尾 `` ` `` 不计），上限 5 个 / ≤16 字母不变。
- **根因 3**：反查段的 affix 剥掉开头 `` ` `` 后，段内容变成「字母+`` ` ``」，混输翻译器按字符形状
  误接管，把解析不了的拼音块折成虎码字母，拼出「一个盘」。修复：混输遇到 `yin_*` 段直接跳过
  （`tools/test_tiger_mixed.lua` 覆盖 6 个 tag + 正向对照）。
- **验证**：`test_pinyin_engine.lua` 29→40 checks、新增 mixed 测试 7 checks、完整回归全绿；
  修复前/后对比：`fjia` 反查|反差|**发内存哈**|梵刹 → 反查|反差|梵刹；`` `fj`ia `` 4 条 → 20 条。

### D14｜快符收敛为单一实现（v0.3.15，2026-11-02）

- **背景**：`kf.dict.yaml`（万象遗留，编码是裸字母 `a`…`z`、未 import 进 `tigress.dict`，实际匹配不到 `;a`）
  与 `lua/tiger_kf.lua`（后加的立即上屏处理器）两份数据并存，符号表已经漂移。

## 10. v0.4.0 拼音反查引擎化（2026-11-02）

### 10.1 决策记录

- **触发形态**：用户明确要求「摒弃万象拼音反查，操作方式/候选呈现不变，变的只是内在」。
  因此没有新开关、新 tag、新前缀：五个反查 tag 原样，`script_translator@yin_add_user`
  换成 `lua_translator@tiger_sentence_pinyin_translator`；查虎码＝候选注释里的
  〔拆分·虎码〕（chaifen 链路原样），` 后缀剥除（db.lua）原样。
- **双实例架构**：`tiger_sentence.lua` 顶层 local 已 198/200，且 `lexicon_state`
  的 rank/primary/learning_rules 全部绑定单码表，拼音码表不能与虎码共表。
  解法：`lua/tiger_sentence_pinyin.lua` 用 dofile 装载同一主 chunk 的第二实例，
  通过新增的 `M.set_data_file_override` 钩子把码表换成 `pinyin.qp.codes.txt`、
  char_ranks/whitelist/supplement 置 false 跳过（虎码语义文件）。顶层 local 现 199/200。
- **键位转换而非五份码表**：双拍 2 键单元 → 全拼音节的映射由
  `tools/export_pinyin_tables.py` 从 `wanxiang_algebra.yaml` 的 `pro/*` 节程序化派生
  （xform/derive/xlit/erase 逐条模拟，与万象 prism 同源）。好处：单份全拼码表、
  五打法全支持、微软/搜狗的 ing `;` 键在转换层消化。首键歧义（mspy/sogou 零声母
  `o` 键）仅影响单键简拼尾，走兜底。
- **候选由 wrapper 自建**：不委托第二实例的 `M.translator`（它没有 tag 白名单，
  会把虎码 abc 段也解码）；preedit 双拍显示键位分组（`fj ia`）、全拼显示引擎
  segmented。学习不参与（无 processor 通知器，decode 的 learning_index 为 nil 且安全）。
- **简拼**：用户选择引擎内组句。实测发现引擎结构性排除单键边（#raw>1 时
  code_length<2 的边不扩展，即上游注释 "A sentence cannot use one-key character
  edges"）→ 简拼靠「词首字母码整段匹配」实现（jsj→计算机），天然免疫 lattice 爆炸；
  字级首字母序列（js）不出候选，与旧 librime 屏蔽简拼行为一致。
- **词表权重线 145**：以「买椟还珠」为锚点定的下限，但总条目上限 25 万把实际
  截断线推到 184（买椟还珠不在词表）。接受：超低频词走辅助码路线，Gate 数据优先。
